## Claims

1. `t=0:42` (frame) Mailer dieline built in Illustrator from plain rectangles
   with inch values; Transform panel shows a **0.125 in × 4 in** strip element —
   an eighth-inch allowance strip alongside the 4×4 in panels.
2. `t=1:42`–`t=2:52` (frames) Preferences panel open with **Keyboard Increment
   = 0.125 in** — panel offsets/allowances are nudged in board-thickness-sized
   steps; 0.125 in ≈ 3.2 mm ≈ B-flute caliper, consistent with corrugate
   needing thickness allowances that folding-carton dielines don't.
3. `t=1:42` (frame) Layout is the classic mailer CROSS: central base panel
   (4 × 4 in) with walls on all four sides, side-wall assemblies carrying
   notched/slotted corner flaps, and a long front-wall + tuck-lid column —
   roll-end tuck-front (RETT-style) construction.
4. `t=2:52` (frame) Tuck-lid and flap corners are ROUNDED by dropping in a
   quarter-circle path (2 in × 2 in element in Transform) and joining — corner
   radii are constructed geometry, not a stroke effect.
5. `t=5:42` (frame) Finished deliverable is an annotated TEMPLATE, not bare
   paths: red outer line + blue inner line per panel, on-canvas legend
   "**Blue line is safe line.** Red …", plus a "Size: (W)_(H)_(D)" caption
   being typeset — the template documents its own line-color convention.

## Engine hooks

- Claim 5 matches the emitter's needs exactly: a shipper/mailer template must
  ship with an in-file legend (cut vs safe line colors) and a W/H/D size
  caption — same self-documenting-template pattern as PackMojo's orientation
  guide; make the legend block a standard emitter output for corrugated
  formats.
- Claim 2 gives corrugate's differentiator from folding cartons: **thickness
  allowances in 0.125 in steps**. Any M7 mailer dieline math must add
  board-caliper allowances between nested panels (ties to Guka's caliper
  table: allowance ≈ flute caliper, so E-flute mailers would step ~1/16 in).
- Claims 3–4: mailer vocabulary for the emitter — cross layout, slotted
  side-wall flaps, constructed corner radii. RETT is the e-commerce default
  format (aligns with EB-flute "subscription boxes" from Guka claim 6).
- Claim 4's constructed-radius method reinforces the standing rule: corner
  geometry is real path work; the engine should not fake radii with rounded
  strokes on a rectangle.
