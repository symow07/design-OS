### A59. Deferring the 36 is an exemption, so it has to cost something visible

"A separate arc for the layout programme to declare" is the right instinct and it is also, in this
programme's own terms, an exemption — and 1r is explicit that an exemption is an affirmative claim
of inertness carrying the burden. Handing a class to a programme that has not accepted it is how
classes escape.

So declare it properly rather than reclassifying it:

1. **`M6-LAYOUT-FALLBACK-AUDIT`** exists as a declared node with the 36 named, not as a note.
2. Until it runs, layout and mechanism records carry
   **`NOT_ESTABLISHED_PENDING_FALLBACK_AUDIT`**, inherited by anything computed from them.
3. If nothing downstream ever consults those records, the deferral costs nothing and that is the
   correct outcome. If something does, the status surfaces at the point of use rather than
   staying invisible.

**And check the severity assumption, because it may run the other way.** You routed the 36 out on
the grounds that they sit outside the powder establishment table — the place where all the law
lives. But layout and mechanism records plausibly feed dielines, and dielines feed physical
output. The powder table gates *verdicts*; layout may gate *geometry that gets cut*. A silent
substitution has consequences there that it does not have in a verdict, and the reflex to treat
the heavily-governed subsystem as the serious one could be exactly backwards for physical risk.

Nothing ships today — manufacturing authority is `NOT_ESTABLISHED` and `GATE_2` is `BLOCKED` — so
this is not urgent. It is a reason the 36 are not obviously the low-severity residue, and the
audit's priority should be set after checking what consumes those records, not before.
